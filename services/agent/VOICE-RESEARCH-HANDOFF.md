# Voice research producers and preview lifecycle

Branch: ws3/voice-research-runtime, based on published e3966d6 contracts. This implements the WS3 side of docs/VOICE-RESEARCH.md. WS1 owns browser adoption/playback. Producers and the extra typed audition tool remain default-off behind GROOVE_VOICE_RESEARCH=1; do not enable on a shared service until both consumer and producer are reviewed/integrated. /healthz exposes the flag without credentials. No user .env or key was modified.

## Behavior

Voice search/refine returns a research-context on the socket event loop before worker progress. Jobs bind original synth/description and deduplicate request IDs; conflicting reuse is rejected. Supersession cancels older running jobs, retires previews and drops late old progress. Failed pre-acceptance voice requests emit a correlated error rather than an unowned failed-job frame the browser would ignore. An accepted context followed by a worker-start failure emits normal matching failed research progress.

Newer UI searches/cancellation defeat already-pending old speech/model results. Speech jobs carry a research epoch; open segments closing later compare the actual aligned wake onset with the latest observed UI capture barrier, not the singing start, padded span or recognition arrival time. Equal frames use socket order for fresh manual transcripts while stopped/offline; previously pending speech is independently guarded by its epoch. Stop/Clear and non-research commands retain their own semantics. Wake speech is excluded before context/preview/error and coverage.

Starting new research is refused while an apply-patch proposal is unresolved or queued in the backend. UI acknowledgment messages do not disclose operation types, so unknown queued UI edits are conservatively treated as possibly pending patch acceptance until final acknowledgment/transport resolution. No interface was invented to guess their type. The original acceptance receipt remains tracked and is not discarded by research replacement.

Audition/preview/listen/hear commands and the gated audition_candidate language tool resolve one ordinal to an exact current job/candidate. Only those IDs are sent; no URL, patch or musical operation comes from the model. Old candidates cannot be previewed/accepted while a newer context has an empty list. Missing preview URL/ambiguous IDs are refused. Preview requests are deduplicated and bounded; new previews replace old ones. Candidate patch/URL changes retire the old binding even if its candidate ID is reused.

preview-ack matches the complete socket-local request/job/candidate tuple. Requested -> started -> ended/rejected is enforced; duplicate started does not extend a deadline, premature ended cannot prove playback, and terminal duplicates cannot act on another request. Start/finish timeouts are 10/135 seconds, leaving delivery margin over the browser consumer's 5/120-second limits. Timeout/rejection is explicit and never changes session revision/patch/notes/capture/Undo. Disconnect closes connection state, cancels its port/worker and drops late callbacks without replay.

## Validation and next gate

Tests use synthetic fixtures/scripted transcribers/models, with actual schema validation and a real WebSocket server. They cover context-before-immediate-worker-progress, original track binding/refine, supersession/duplicate IDs, old closed/open speech versus newer UI (including a fresh wake after older singing), delayed model rejection, pending voice/UI edits, unavailable/duplicate candidates, exact preview acknowledgments, blocked playback, start/finish deadlines, stale completion, bounded history and disconnect. A fresh manual acceptance at the same stationary frame is protected from false stale rejection.

The prior regression expecting a new refinement during unresolved patch acceptance now explicitly tests rejection, settles its acceptance acknowledgment and only then starts another job. Legacy/default-off cancelled-refinement candidate fallback remains covered. observe_research now returns an empty frame list for valid progress or None for retired/unknown/closed jobs; this is internal callback routing, not a wire change.

Full results and commit are recorded in the PR. Existing shared checks/live service/WASM integration passed; the real-renderer/MOCK-embedder research regression is also required. These do not prove CLAP quality, live-provider corpus accuracy or human hearing.
